

## **المواصفات الفنية: تكامل الحضور بالبصمة**

المهمة ID: TASK-1.4  
المرحلة: 1 \- بناء الأساس التشغيلي والتجاري  
الوثائق ذات الصلة: Arkan\_Labs\_Workspace\_Management\_System (v1.0)

### **1\. الهدف**

أتمتة عملية تسجيل الحضور والانصراف للموظفين في مساحة العمل عن طريق المزامنة المباشرة مع أجهزة الحضور بالبصمة، مما يلغي الإدخال اليدوي ويوفر بيانات دقيقة وموثوقة.

### **2\. التحليل التقني والتصميم**

سنعتمد على الأداة الرسمية التي توفرها Frappe لهذه المهمة، مما يقلل بشكل كبير من جهد التطوير المخصص.

#### **2.1. الأداة المعتمدة**

* **frappe/biometric-attendance-sync-tool**: هي أداة Python مستقلة مصممة خصيصًا لسحب سجلات الحضور من أجهزة البصمة (مثل ZKTeco) ودفعها إلى DocType Checkin في منصة Frappe/ArkanNG عبر واجهة برمجة التطبيقات REST.\[17, 18\]

#### **2.2. خطوات التنفيذ والتكوين**

1. **تثبيت الأداة:** سيتم تثبيت الأداة في بيئة Python منفصلة على خادم يمكنه الوصول إلى كل من شبكة أجهزة البصمة والإنترنت (للوصول إلى ArkanNG API).  
   Bash  
   pip install biometric-attendance-sync-tool

2. **التكوين (config.ini):** سيتم إنشاء ملف تكوين يحدد تفاصيل الاتصال:  
   * **\[frappe\_server\]**:  
     * base\_url: عنوان URL لمنصة ArkanNG.  
     * api\_key: مفتاح API لمستخدم مخصص لديه صلاحيات إنشاء سجلات Checkin.  
     * api\_secret: سر API المقابل.  
   * **\[biometric\_devices\]**:  
     * قائمة بعناوين IP والمنافذ الخاصة بكل جهاز بصمة في مساحة العمل.  
3. **ربط الموظفين:**  
   * يجب التأكد من أن Attendance Device ID في سجل Employee في Frappe HR يطابق معرف المستخدم المسجل على جهاز البصمة. هذا هو المفتاح لربط سجل الحضور بالموظف الصحيح.  
4. **التشغيل المجدول:**  
   * سيتم إعداد مهمة cron على الخادم لتشغيل الأداة بشكل دوري (على سبيل المثال، كل 5 دقائق) لسحب السجلات الجديدة.  
   * الأمر: biometric-attendance-sync-tool \--config /path/to/config.ini

### **3\. التقنيات والمكتبات الرئيسية**

* **frappe/biometric-attendance-sync-tool**: الأداة الأساسية.  
* **Linux:** cron لجدولة المهام.  
* **Frappe HR:** DocType Employee (لتخزين Attendance Device ID) و DocType Checkin (لتخزين السجلات).

### **4\. معايير القبول**

* عندما يقوم موظف بتسجيل الدخول أو الخروج باستخدام جهاز البصمة، يجب إنشاء سجل Checkin جديد في ArkanNG خلال 5 دقائق.  
* يجب أن يكون سجل Checkin مرتبطًا بالموظف الصحيح.  
* يجب أن يتمكن مديرو الموارد البشرية من رؤية هذه السجلات في تقارير الحضور.

### **5\. المخاطر المحتملة والتخفيف منها**

* **الخطر:** انقطاع الشبكة بين خادم المزامنة وأجهزة البصمة أو منصة ArkanNG.  
  * **التخفيف:** الأداة مصممة لتكون متسامحة مع الأخطاء؛ ستقوم بمزامنة السجلات التي لم تتم مزامنتها عند استعادة الاتصال. يجب إعداد نظام تنبيهات (باستخدام RabbitMQ) لمراقبة نجاح مهام cron.  
* **الخطر:** عدم تطابق معرفات الموظفين بين النظام والجهاز.  
  * **التخفيف:** يجب توثيق عملية إلحاق الموظفين بوضوح لضمان أن يقوم فريق الموارد البشرية بتعيين Attendance Device ID الصحيح كجزء من قائمة التحقق الخاصة بإلحاق الموظف الجديد.
