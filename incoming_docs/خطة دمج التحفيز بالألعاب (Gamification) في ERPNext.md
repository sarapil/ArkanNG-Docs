# **خطة دمج التحفيز بالألعاب (Gamification) في ERPNext \- الإصدار 1.0**

## **1\. الأهداف الاستراتيجية**

يهدف هذا المشروع إلى تحويل تجربة استخدام نظام ERPNext من مجرد أداة إدارية إلى بيئة عمل تفاعلية ومحفزة. الأهداف الرئيسية هي:

* **زيادة تبني النظام (User Adoption):** تشجيع الموظفين على استخدام النظام بشكل يومي ومستمر.  
* **تحفيز الأداء (Performance Boost):** ربط أهداف الألعاب بمؤشرات الأداء الرئيسية (KPIs) للأقسام.  
* **تحسين جودة البيانات (Data Quality):** مكافأة الموظفين على إدخال البيانات بشكل كامل ودقيق.  
* **تعزيز روح الفريق (Team Spirit):** إنشاء تحديات جماعية ومنافسة شريفة.

## **2\. المكونات الأساسية لنظام التحفيز**

سيتم بناء النظام حول المكونات التالية:

* **النقاط (Points \- XP):** الوحدة الأساسية للمكافأة.  
* **الشارات (Badges):** إنجازات مرئية تُمنح عند تحقيق أهداف محددة.  
* **لوحات الصدارة (Leaderboards):** عرض قائمة بالموظفين الأعلى نقاطًا (يومية، أسبوعية، شهرية).  
* **المستويات (Levels):** نظام تقدم يعكس خبرة المستخدم وتفاعله مع النظام.  
* **التحديات (Challenges):** مهام محددة (فردية أو جماعية) مع مكافآت خاصة.

## **3\. الخطة التقنية للتنفيذ (عبر Frappe Framework)**

سيتم بناء **تطبيق Frappe مخصص** ومنفصل باسم GamifyApp لضمان عدم المساس بالكود الأساسي لـ ERPNext.

### **3.1. تصميم نماذج البيانات (DocTypes)**

سنقوم بإنشاء DocTypes جديدة في GamifyApp:

1. **Gamification Rule:** قلب النظام، ويحتوي على:  
   * **Source DocType:** (مثال: Lead, Sales Order).  
   * **Trigger Event:** (مثال: On Submit, On Update).  
   * **Conditions:** شروط إضافية (مثال: doc.status \== 'Converted').  
   * **Points to Award:** عدد النقاط.  
   * **Badge to Award:** رابط إلى DocType Gamification Badge.  
2. **Gamification Badge:** لتخزين معلومات الشارات (الاسم، الوصف، أيقونة).  
3. **User Score:** سجل مرتبط بكل User لتخزين إجمالي نقاطه ومستواه وشاراته.  
4. **Leaderboard:** لإنشاء لوحات صدارة مختلفة (مثل "أفضل بائع هذا الشهر").

### **3.2. تنفيذ منطق العمل (Business Logic)**

سنستخدم **Frappe Hooks** لربط الأحداث في ERPNext بنظام الألعاب.

* في ملف hooks.py داخل تطبيق GamifyApp:  
  \# hooks.py in GamifyApp  
  doc\_events \= {  
      "Lead": {  
          "on\_update": "gamifyapp.gamify.handle\_doc\_event"  
      },  
      "Sales Order": {  
          "on\_submit": "gamifyapp.gamify.handle\_doc\_event"  
      },  
      "Support Ticket": {  
          "on\_update": "gamifyapp.gamify.handle\_doc\_event"  
      }  
  }

* ستقوم دالة handle\_doc\_event بالبحث في Gamification Rules. إذا تطابقت الشروط، ستقوم بتحديث User Score الخاص بالموظف ومنحه النقاط والشارة.

### **3.3. واجهة المستخدم (UI)**

* **لوحات الصدارة:** سيتم إنشاؤها كـ Report قياسي في Frappe.  
* **ملف المستخدم:** سيتم تخصيص صفحة My Settings لإضافة قسم يعرض نقاط المستخدم وشاراته.  
* **الإشعارات:** استخدام نظام الإشعارات في Frappe لإرسال تنبيه فوري للمستخدم عند حصوله على مكافأة.

## **4\. مقترحات عملية للتطبيق**

### **4.1. لفرق المبيعات:**

* **\+10 نقاط:** إنشاء عميل محتمل جديد بمعلومات كاملة.  
* **\+50 نقطة:** تحويل عميل محتمل إلى فرصة بيع.  
* **\+200 نقطة:** إتمام صفقة (Sales Order).  
* **شارة "النجم الصاعد" ⭐:** تُمنح عند إغلاق أول صفقة.

### **4.2. لفرق خدمة العملاء:**

* **\+20 نقاط:** حل تذكرة دعم فني.  
* **\+30 نقطة إضافية:** إذا تم حل التذكرة في أقل من ساعة.  
* **شارة "المنقذ السريع" 🚑:** تُمنح عند حل 5 تذاكر في نفس اليوم.

### **4.3. لجميع الموظفين:**

* **\+5 نقاط:** تسجيل الدخول اليومي.  
* **\+15 نقطة:** إكمال مهمة (To-Do) في الوقت المحدد.  
* **شارة "المواظب" ⏰:** تُمنح عند تسجيل الدخول 5 أيام متتالية.

## **5\. مراحل التنفيذ (Roadmap)**

* **المرحلة الأولى (الأساس \- شهر واحد):**  
  * بناء تطبيق GamifyApp مع DocTypes الأساسية.  
  * تطبيق قاعدتين لقسم المبيعات.  
  * إطلاق النظام بشكل تجريبي على فريق المبيعات.  
* **المرحلة الثانية (التوسع \- شهران):**  
  * بناء واجهات لوحات الصدارة وملفات المستخدمين.  
  * إضافة قواعد لفرق الدعم الفني والمشاريع.  
* **المرحلة الثالثة (التفاعل المتقدم \- 3 أشهر):**  
  * تطوير نظام التحديات الأسبوعية.  
  * إنشاء "متجر مكافآت" افتراضي لاستبدال النقاط.
